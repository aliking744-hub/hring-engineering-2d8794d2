# چک‌لیست UAT استیجینگ — PR744 و PR66

این سند برای اجرای یک‌باره پس از همگام‌سازی شاخهٔ آماده‌سازی با main و قبل از هر تصمیم برای تولید است.
هیچ موردی با «سالم بودن کانتینر» به‌تنهایی قبول نمی‌شود.

## پیش‌نیازها

- migrationها تا head اجرا شده‌اند.
- سرویس‌های API، Web، Worker، AI، PostgreSQL، Redis و MinIO سالم‌اند.
- یک حساب مدیر شرکت و یک حساب نقش محدود برای کنترل مجوزها وجود دارد.
- یک Provider مدیریت‌شدهٔ HRing سالم و در صورت تست BYOK، یک کلید آزمایشی محدود آماده است.
- برای هر اجرای تولید AI، یک کلید idempotency یکتا استفاده می‌شود.

## قراردادهای PR66: استقلال، امنیت و هزینه

| سناریو | اقدام | نتیجهٔ قبولی |
|---|---|---|
| کلید اختصاصی شرکت | در تنظیمات شرکت برای یک قابلیت AI، Provider/adapter/base URL/model/secret وارد و «تست اتصال» اجرا شود | کلید پس از ذخیره قابل مشاهده نیست؛ فقط mask نمایش می‌گیرد؛ تست موفق، وضعیت healthy و زمان آخرین تست را ثبت می‌کند. |
| کلید نامعتبر | همان اتصال با کلید نامعتبر تست شود | خطا بدون افشای secret ثبت می‌شود؛ قابلیت روی Provider پلتفرم fallback نمی‌کند. |
| مسیر مدیریت‌شده | حالت HRing Managed انتخاب و ذخیره شود | پنل آن را «مدیریت‌شده» نشان می‌دهد، نه «نیازمند تست». هزینهٔ اجرای موفق از اعتبار شرکت کم می‌شود. |
| BYOK و هزینه | برای قابلیت سالمِ BYOK یک تولید واقعی اجرا شود | خروجی ساخته می‌شود، اعتبار مدیریت‌شده کم نمی‌شود و اجرای هم‌زمان همان idempotency key دوباره Provider را فراخوانی نمی‌کند. |
| جداسازی tenant | دو شرکت برای یک قابلیت، کلید متفاوت ثبت کنند | هیچ کاربر یا درخواست شرکت A به secret/پیکربندی شرکت B دسترسی ندارد. |
| مجوزها | با نقش فاقد company.integrations.manage صفحهٔ تنظیمات شرکت باز شود | مشاهده یا ویرایش دقیقاً مطابق مجوز است؛ تغییر اتصال ممکن نیست. |

## قراردادهای PR744: خروجی AI و تجربهٔ محصول

| قابلیت | ورودی UAT | نتیجهٔ قبولی |
|---|---|---|
| تولید آگهی هوشمند | نقش، شرکت، پلتفرم، لحن و انتخاب تولید تصویر وارد شود | نتیجهٔ متن در خود صفحه ظاهر می‌شود؛ toast موفقیت بدون خروجی پذیرفته نیست؛ پلتفرم و لحن در خروجی اثر قابل‌مشاهده دارند. |
| تولید پروفایل/شرح شغل | عنوان نقش و زمینهٔ شرکت وارد شود | خروجی ساختاریافته و قابل‌استفاده برمی‌گردد و تاریخچه قابل بازیابی است. |
| کیت مصاحبه | یک نقش واقعی آزمون وارد شود | سوال‌ها، rubric و راهنمای امتیازدهی برمی‌گردد؛ خروجی خالی یا markdown نامعتبر رد است. |
| یادگیری و ایمیل | پروفایل کارمند و محدودیت زمانی آموزش وارد شود | مسیر واقع‌بینانه با یک تمرکز اصلی در هر ماه ساخته می‌شود؛ ارسال ایمیل فقط با ایمیل معتبر موفق است. |
| حقوقی | یک سناریوی واقعیِ بدون دادهٔ حساس تست شود | پاسخ همراه با منبع/استناد برمی‌گردد؛ منبع جعلی پذیرفته نیست. |
| پشتیبانی | یک سوال دربارهٔ قابلیت واقعی HRing بپرسید | SSE کامل و پاسخ منطبق با قابلیت‌های فعال برمی‌گردد؛ قابلیت حذف‌شده معرفی نمی‌شود. |

## گردش‌کار واقعی آنبوردینگ

1. در «معمار موفقیت ۹۰ روزه»، نام کارمند، عنوان شغل، سطح، انتظار، منتور و تاریخ شروع را وارد کنید.
2. تولید را یک‌بار اجرا کنید؛ باید برنامهٔ AI، ایمیل خوش‌آمدگویی و پنج تسک آغازین روزهای ۱/۷/۳۰/۶۰/۹۰ ایجاد شود.
3. وارد «نقشه راه ۹۰ روزه» شوید؛ همان کارمند و تسک‌ها باید نمایش داده شوند.
4. یک تسک را تکمیل و سپس دوباره باز کنید؛ درصد پیشرفت، زمان تکمیل و رخدادهای «تکمیل/بازگشایی» باید ذخیره شوند.
5. یک تسک تازه با مسئول و موعد بسازید؛ پس از refresh هم باید باقی بماند.
6. با کاربر دیگر، برنامهٔ کاربر اول نباید قابل خواندن یا ویرایش باشد.

## خروج نهایی

فقط وقتی همهٔ ردیف‌های فوق گذر کردند:

1. خروجی migration و نسخهٔ imageها ثبت شود.
2. بکاپ تأییدشده پیش از استقرار گرفته شود.
3. smoke و regression suite اجرا و نتیجه پیوست شود.
4. نتیجهٔ هر مورد UAT، خطا و تصمیم رفع آن ثبت شود.
5. فقط با تأیید صریح مالک محصول، تصمیم استقرار تولید گرفته شود.
